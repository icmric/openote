# Openote v0.2 — first public release plan

> **Document status:** Draft v0.1 · Planning · 2026-07-27
> **Owner:** Eric · **Related:** [ROADMAP](../../ROADMAP.md) · [Phase 1 exit review](../reviews/2026-07-code-review-phase1-exit.md) (§A–§S) · [ADR-0006](../adr/ADR-0006-sync-transport-and-text-model.md)
> **Scope discipline:** everything here traces to a PRD requirement, a review finding, or the vision's differentiators. Sizes are honest guesses for one developer working with AI sessions: **S** ≈ hours · **M** ≈ 1–3 days · **L** ≈ a week · **XL** ≈ multi-week.

## 1. What this release is

**The release a stranger can use.** The licence is ratified, so the repo is legally open — but "open source project" isn't true in practice until someone who isn't us can download an installer, import their OneNote notebook, and do a week of real note-taking without hitting a data-loss bug or a missing basic.

**Proposed headline:** *"Import your OneNote notebook. Keep it in an open format. Use it on two devices."*

Sync is the headline on purpose: it answers OneNote's #1 complaint, ADR-0006's groundwork is built and verified in shadow mode, and no competitor at our intersection has it. Tags are the parity anchor (the one signature OneNote subsystem we lack entirely). Live embeds are the stretch headline — see §8.

**Version:** `0.2.0`, tagged. This is also the moment the [File Format Spec](../specs/10-file-format-spec.md) says format v1 freezes — a real deliverable, not a formality (§9).

## 2. Release exit checklist

The release ships when every box is true. Everything else in this document is in service of these.

- [ ] CI green on Windows, macOS, Linux — and the app has been **run by a human** on each
- [ ] Downloadable artifacts for all three OSes; a stranger goes download → imported notebook in under 10 minutes using the README alone
- [ ] No open bug that can lose or corrupt user content
- [ ] The 324-page reference notebook: re-imports cleanly, edits, and passes rebuild-from-log verification with zero divergence
- [ ] Two-device sync works over a plain synced folder (the ADR-0006 promise, delivered at MVP level)
- [ ] Tags exist: imported notebooks stop dropping them, and a user can add/find them
- [ ] Format v1 + op-log v1 frozen, with the compatibility promise stated publicly
- [ ] `CHANGELOG.md` exists; contributing docs match reality

## 3. Tier 0 — verification & release engineering *(do first; mostly S)*

Cheap, and everything else is unverified until it's done.

| Item | Why | Size |
|---|---|---|
| **Push and fix CI's first run** | The workflow has never executed; the Rust jobs and macOS/Linux app jobs are written blind. Expect one round of fixes. | S–M |
| **First real macOS + Linux build/run** | PLAT-1 claims all three OSes; only Windows has ever run. This is the single least-defensible claim in the docs. | M (unknowns) |
| **Wire the CMake hook so `flutter build` builds the Rust core** | The stale-DLL trap has burned multiple sessions; strangers will hit it in minutes. `INTEGRATION.md` documents the hook — wire it. | S |
| **Release packaging** | Windows: portable `.zip` + optional MSIX. Linux: AppImage (Flatpak later). macOS: `.dmg`. A `release.yml` workflow building all three from a tag. | M |
| **Touch drawing on real hardware** | The C-8 fix is unit-tested logic; gesture *feel* (grace window, pinch cancel) has never met a Surface or tablet. Also the Phase-0 ink feel-check residue. | S (needs hardware) |
| **Versioning + `CHANGELOG.md`** | Start the discipline at the first tag, not after. | S |

**Decision needed:** macOS signing/notarization costs an Apple developer account ($99/yr). Unsigned DMGs trigger Gatekeeper warnings. Recommend: ship unsigned for 0.2 with a documented `xattr` workaround; revisit if mac adoption appears.

## 4. Tier 1 — data-safety and correctness fixes *(before any new feature)*

Known defects, carried openly in the roadmap — a public release turns them from "known" into "shipped".

| Item | Defect | Size |
|---|---|---|
| **Markdown emitter indent-level loss** | Importer sometimes encodes fewer indent levels than the source; every affected row carries a residual horizontal offset. Last known layout bug. | M (parser) |
| **Silent ink-stroke drops** | ~0.02 % of strokes are undecodable and vanish with no signal. Route through the existing import-warnings channel ("3 ink strokes could not be read"). | S |
| **Symbol/Wingdings PUA mapping** | `U+F0xx` chars currently render only because those fonts are in the fallback chain. Map the *unambiguous* subset (Symbol's math operators) to real Unicode at import; leave ambiguous cases (0xAC arrow-vs-negation) alone, per §N.3. | M |
| **Imported image `y` validation** | Width/height verified to 0.03 mm; `y` never independently checked (the check was circular). Needs one fresh OneNote PDF export of an affected page — **requires your OneNote access, nothing else**. | S |
| **Remaining §E-3 leaks** | Two undisposed `TextEditingController`s, an undisposed `ValueNotifier`, `AppState.canvas` disposal. | S |
| **Ink-block op-log bloat measurement** | Block-level ops mean each erase gesture re-records the whole ink block. On the 65k-stroke notebook this could balloon the log. **Measure first**; if real, the mitigation is per-stroke ops (a new op kind — the envelope was versioned for exactly this). | S measure, M fix |

## 5. Tier 2 — the switcher parity cluster

The review's §H table, updated. Each is small, high-frequency, and felt within the first hour of switching. Ordered by how often a user hits them.

| Item | Requirement | Size | Notes |
|---|---|---|---|
| **Paste / drag-drop images** | MEDIA-1 | M | Needs `pasteboard` + `desktop_drop` (both BSD/MIT — re-run the licence audit). The last "basic" a switcher misses daily. |
| **Drag-to-reorder pages/sections** | ORG-2 | M | Menu-driven today. The navigator already has drag *targets* for re-parenting; extend to sibling reorder using the fractional-index positions. |
| **Height/corner resize + ink scaling** | CANVAS-4 | M–L | Width-only today. Ink scaling needs a decision: scale stroke coordinates (recommended — matches OneNote) vs. clip. |
| **Group/ungroup + alignment guides** | CANVAS-7 | L | The largest parity item. Guides alone (snap lines to neighbours while dragging) deliver half the perceived value for a third of the cost — split them and do guides first. |
| **Whole-stroke eraser mode** | INK-6 | S–M | Area eraser exists; add a mode toggle on the Draw tab. |
| **Lasso: resize/recolor** | INK-7 | M | Gathering works; add handles + a recolor action on the selection. |
| **Bundle Inter + JetBrains Mono** | Style guide §4.1 | S | Kills per-OS font variance; OFL licences → add to LICENSING.md. The fallback chain stays for symbols. |
| **Notebook-wide find** | TEXT-7 | M | Needs the FTS decision (§10). Replace can follow in 0.3; find across the notebook is the felt gap. |
| **Built-in page templates** | ORG-9 | S | The feature works; a fresh install just shows an empty list. Ship 5–6 (Cornell notes, meeting, weekly plan, math worksheet…). Pure content. |
| **Spell-check** | TEXT-11 | spike S | Flutter's `SpellCheckConfiguration` is mobile-first; desktop support is uncertain. **Spike before committing** — if it needs a native dictionary per OS, defer to 0.3 explicitly rather than half-shipping. |

## 6. Tier 3 — Tags (TEXT-5): the one big missing subsystem

OneNote users organise their lives around tags; the importer currently **drops them silently**. This is the largest single feature of the release and needs a short design pass before code. Recommended shape:

- **Model:** per-paragraph tag markers (OneNote's model), stored as a `tags` array on the block envelope (Data Model Spec change, S). *Not* inline `#hashtags` — that's Obsidian's model and collides with our Markdown heading syntax.
- **Core set + custom:** map OneNote's built-ins to a core set (To-Do ☐, Important ★, Question ?, Remember, Definition, Highlight, Critical, …) with icon + colour; user-defined tags beyond that.
- **UI:** a tag button + picker on the Home tab; markers render in the paragraph gutter; click a To-Do to toggle it (it's a checkbox with an identity).
- **Find-tags rollup:** a panel listing every tagged paragraph in the notebook, grouped by tag, clickable — OneNote's "find tags" is half the feature's value.
- **Importer:** map OneNote tag IDs (the `.one` property exists — reverse-engineer the ID table from the reference notebook) onto the core set; unknown IDs become custom tags, **never dropped**.
- **Op log:** tags ride inside block content — no new op kind needed.

Sizes: model S · editor+gutter M · picker M · rollup panel M · importer M · spec update S. **Total ≈ XL, but cleanly partitionable** — the model+import half alone stops the data loss and could ship even if the UI polish slips.

## 7. Tier 4 — Sync: from shadow to "my two devices"

The arc continues from the built groundwork. The MVP cut deliberately **avoids demoting the container** — the `.onotebook` directory is the synced unit; each device keeps its own `.onote` as a private materialisation. The "flip" to `cache.onote` stays out of this release.

1. **Real-notebook verification** (S): re-import the 324-page notebook on the current binary, run rebuild-from-log against every page, publish the result in the review log. The exit-checklist item.
2. **Sync status surface** (S–M): a small panel — device id, ops written, missing blobs, last verify result, "this notebook's sync folder". Trust needs visibility.
3. **Foreign-log ingestion** (M–L): watch `ops/` for logs from other devices; replay new ops into the open notebook live (page-scoped refresh). This is the moment sync *exists*.
4. **Notebook-in-a-synced-folder flow** (M): "Move notebook to a synced folder…" action + folder watcher. With one-writer-per-file, Drive/OneDrive/Syncthing does the transport; we do ingestion. No network code.
5. **Two-device soak test** (S, needs your second machine): the exit-checklist scenario, run for real.
6. **Blob fetch policy** (decision, §10): eager is fine at folder-sync scale; decide lazily-with-placeholder only if it proves painful.

**Explicitly out:** Loro / the structured-`nodes` migration (same-paragraph concurrent editing is a collaboration feature, not a two-device feature), our own sync service, E2E encryption (envelope stays reserved).

## 8. Tier 5 — headline candidates & small delighters

- **Live embeds MVP** (EMBED-2..8, **XL**): the vision's flagship differentiator — render a block/range of another page, read-only, live, cycle-safe. The data model reserved space for it from the first byte. **Recommendation: in only if Tiers 0–4 land early.** It deserves a focused iteration, not a squeezed one; a slipped flagship hurts more than a deferred one. If deferred, 0.3 becomes "the embeds release" with graph view alongside.
- **Page outline / TOC** (TEXT-10, M): heading-derived outline panel for long pages. Small, differentiating, pairs with imported lecture notes.
- **Favourites & recents** (ORG-10, S): star pages; a recents list in the switcher.
- **Auto-sort** (ORG-8, S): sort sections/pages alphabetically/by-date from the context menu.

## 9. Format freeze *(release-gated, mostly review work)*

The spec says v1 freezes when the MVP ships. That means, before tagging:

- Freeze the container schema (`page_mirror` shape, block envelope) and **op-log v1** (envelope fields, op kinds, ordering rule) — a compatibility review pass over both specs against the code as-built (M).
- State the promise publicly in the README: *notebooks created in 0.2 open in every future version*.
- Add the changelog section the spec reserves.
- Decide `.onotebook` manifest v1 final fields (scope object shape is already decided).

## 10. Open decisions — take at kickoff, not mid-build

1. **Is 0.2 public, or a private milestone?** Everything above assumes public. If private, Tier 0's packaging drops to "CI + run on three OSes" and the release compresses by ~a week.
2. **Embeds in or out** (§8). Recommendation: out unless ahead of schedule by Tier 4.
3. **Spell-check** after the spike: ship, or defer explicitly.
4. **FTS reintroduction** for notebook-wide find: the empty `fts_pages` was removed for honesty; notebook-wide find wants it back *populated*, declared via `notebook_meta.features` per spec. Alternative: brute-force scan of mirrors (fine to ~1k pages, simpler). Recommend: brute-force for 0.2, FTS when it measurably hurts.
5. **macOS signing** (§3).
6. **Blob fetch policy** (§7) — only if the soak test hurts.
7. **Tag core-set contents** — pick the built-ins list (10 minutes with OneNote open).

## 11. Suggested order of attack

```
Tier 0 (verify everything) ─┬─► Tier 1 (safety fixes)
                            │
                            ├─► Tier 4.1–4.2 (verify sync on the real notebook)
                            │
        Tier 2 parity ◄─────┴─► Tier 3 tags (model+import first)
        (interleave small items between larger ones)
                            │
                            ▼
        Tier 4.3–4.5 (sync MVP) ──► §9 format freeze ──► tag 0.2.0
                            │
        Tier 5 only if early ┘
```

Structural debt (the `AppState`/`sidebar.dart` splits, `onenote.rs` module split, §E-5 duplication folds) is **not a tier** — each split is done *when a feature first touches that file*, so the debt pays for itself: tags forces the sidebar split; importer round 2 forces the `onenote.rs` split.

## 12. Explicitly not in this release

Loro / structured `nodes` · real-time collaboration · our own sync service · E2E encryption (reserved) · ink recognition · OCR · web clipper · audio · phone/web builds · math evaluation/CAS · plugin API · graph view · minimap / LOD rendering (CANVAS-9/10) · vector PDF export · MathML/HTML export. Each stays on the long-term roadmap; naming them here is what keeps the release finishable.

### Deliberately not done, with reasons

- **OneNote tag import.** The investigation found the MS-ONE property IDs are unverified against a real tagged file, *and* a latent parser bug in the same code path: property type `0x10` is mis-sized, which desynchronises every property after a tag array on a tagged paragraph. Fixing that blind risks imports that work today. It needs a small `.one` file containing a To-Do, an Important, a Question and one custom tag, dumped with `cargo run --example dump_one`.
- **Image paste / drag-drop (MEDIA-1)** — needs two new packages; deferred rather than added unverified late in the pass.
- **Canvas parity (CANVAS-4/7, ORG-2)** — the "feels unfinished" cluster. Alignment guides alone would deliver most of the perceived value.
