# v0.21 — Outdo OneNote at maths

> The owner's brief, verbatim: *"i want it to be one of if not the most
> comprehensive maths editor avalible in a notebook around (of course we cant
> quite do wolfram alpha level things with it due to the insane complexity of
> it, but i recon we can outdo onenote in this department and come up with
> something even better, even though onenote is already leauges ahead of any
> other platform here)."*

This plan is the product of the 2026-08-20 full review: four analyst agents
(completeness, code quality, test coverage, competitive research), every
code-quality finding adversarially verified, and the researched half checked
against Microsoft's own support pages, pub.dev, and the Obsidian/Notion
plugin ecosystems.

## Where Openote already stands (post-review, commits 482b9e2..22c2133)

The architecture is ahead of every notebook competitor: an owned linear
grammar, an owned editing tree, canonical-LaTeX storage, one shared editor
for block and inline placement, mouse and keyboard selection, and a FREE
calculator where OneNote paywalls its Math Assistant behind M365 Education.
The review's confirmed defects in that stack are now closed:

* the calculator evaluates the visual tree (it fed LaTeX to a linear-only
  parser and was dead for every fraction, power and root);
* matrices grow columns (`&`) as well as rows (Enter);
* `$$…$$` display maths survives editing; `$ x $` padded maths is read;
  Ctrl+$ climbs inline → display;
* maths renders in tables, on flashcards, in study review;
* paste is parity everywhere: refuse-don't-corrupt in the editor, maths →
  math block on the canvas, cut-block-then-paste restores the block;
* the in-place session survives foreign rewrites (undo, toolbar Bold);
* saved empty slots draw their square in read mode and print;
* the import repair no longer eats dollars between two equations (Rust);
* equations carry first Semantics labels.

## The ranked list — what beats OneNote next

Value-per-effort order, from the researched comparison. "Owner decision"
marks items that need a vision call, not just work.

### 1. Multi-line aligned derivations, editable (quick-win, HIGH)

`\begin{aligned}` RENDERS today (latex_compat maps align/align*/split onto
it) but `MathEditor.open` returns null — so every line-by-line derivation,
the core university note-taking act, drops the student into raw LaTeX. The
grid machinery already exists: `MMatrix` takes an env string, Enter adds a
row, `&` now adds a column. Adding `aligned` to `_matrixEnvs`
(math_parse.dart:95) plus one palette chip ("multi-line working") reuses all
of it. This is the single thing Overleaf/Obsidian users most cite as why
they left OneNote — OneNote has no align at all.

### 2. Graph from the equation — **now designed in full: [v0.22](v0.22-graphs.md)**

OneNote's "Graph in 2D" requires M365 Education; students without it
alt-tab to Desmos and screenshot. Openote owns every piece needed: extend
the evaluator with a variable binding (`Map<String,double>` for x, ~20
lines), sample 300–500 points, draw axes + curve in a CustomPainter block.
Offline, free, no Desmos account. **Caveat recorded honestly: spec 12 §1
and evaluate.dart both list graphing as a Vision §9 non-goal.** The
calculator set the precedent of undercutting OneNote's paywall when the
cost is a few hundred owned lines; this is the same move — but it needs an
explicit vision amendment from the owner first. v1 scope: one function of
x, auto-range, re-edit affordance; no pan/zoom/multi-series.

### 3. Solve-for-x, the school subset with honest steps (worth-planning)

OneNote's marquee paid feature. A full CAS stays a non-goal, but the actual
school usage is three templatable cases — linear (isolate x), quadratic
(factor / formula / complete-the-square), 2×2 simultaneous — all with
genuinely honest steps derivable from the owned tree (~800 lines in the
evaluate.dart house style). Everything else: numeric root-finding with no
steps, labelled as such. pub.dev CAS packages were assessed and rejected
(math_expressions: no solve; advance_math: unaudited kitchen-sink).
Sequenced AFTER graphing — they share the variable-binding substrate. A
polynomial derivative command falls out of the same walk.

### 4. Units now, conversion later (quick-win slice)

`9.8 m/s^2` renders as italic variables today. Quick slice: `\unit(m/s^2)`
sugar in linear_math (the `\dx` pattern) emitting `\,\mathrm{…}`, plus a
Units row in the inventory (m s kg N J W Hz mol °C — the science category
has six symbols and no units). Later: unit conversion in the calculator
("5 mi in km", a dimension-vector table, ~200 lines) — a Soulver feature no
notebook app has.

### 5. Chemistry: a \ce subset that expands to plain LaTeX (quick-win slice)

mhchem is a preprocessor by design, so a `\ce(...)` sugar expanding the
useful subset — auto-subscripts (H2O → H₂O), charges, → and ⇌, upright
state symbols — emits LaTeX the renderer already draws. The formulas-only
slice (digit subscripting) is small. No notebook app does chemistry input
at all; visible first for year-10-12 students.

### 6. Equation numbering + cross-references (worth-planning, university tier)

"Substituting (3) into (7)". Nobody has it built in — Obsidian needs
plugins, OneNote nothing. Display blocks get an optional per-page
auto-number, `\label` stores on the block, an inline reference chip renders
the live number and renumbers on insert/delete (the same live-span
machinery inline maths uses). Real effort: renumbering, PDF export,
dangling-ref UX. One page per scope for v1.

### 7. Spoken maths + MathML (worth-planning; procurement matters)

The Semantics labels added this round carry the LaTeX string — honest but
jargon. The real fix is two walks over the tree Openote already parses:
a spoken-English string ("x squared over two, times pi") for Semantics,
and Presentation-MathML at export. OneNote DOES read equations aloud
(Immersive Reader), so this is parity with the incumbent, and school
procurement increasingly requires it.

### 8. Ink-to-math — deferred, with the reasons recorded

OneNote paywalls it, so it is tempting — but every recognizer path on
Windows desktop is heavy (ML Kit is mobile-only, MyScript is commercial,
Seshat/TrOCR mean C++/ONNX embedding). Two outs, recorded: the lossless
stroke store means this lands later with zero data migration; and the MCP
external API is the near-term bridge — a tool exposing strokes lets a
user's AI do the recognition and write the math block back.

## Housekeeping the review left open (small, tracked)

* Read-mode inline overflow: `FittedBox(scaleDown)` on the atom risks the
  measured baseline parity (`RenderFittedBox` reports no baseline) — needs
  its own probe before building. The wrap predictor still sees maths as
  0 px wide (`_SourceSpan.width`); a measured-width cache is the lever.
* Per-keystroke latency: still unmeasured after four rounds; 40 inline
  equations measured 87.7 ms/keystroke in the review probe. The v0.19 atom
  cache ("an atom widget is built once per id, never per keystroke") is
  designed and unbuilt.
* Recents persistence: v0.18 §5.2 promised per-workspace persistence; the
  code carries a reasoned decision AGAINST it (nobody misses it across a
  restart). Owner to break the tie; either answer is one line of plan text.
* Test gaps still open: EquationSourcePanel (zero tests), a dark-mode
  sweep of the tints, the Markdown export→import equation round trip.
* The evaluator has no multi-arg functions (gcd(12,8), max(a,b)) though
  the palette offers them — comma support in evaluate.dart.
