## 3. What we are building, in plain words

You press Alt+= (or the Σ button) and type `1/2`. The moment you press space,
the characters **become** a fraction — a real one, drawn small and true,
right where you were typing. Insert a square root from the bar and you get a
√ sign with a small dotted box under it; your caret is already in the box.
Tab hops to the next box. Escape puts you back in your sentence, and the
equation sits **in** the sentence, on the same line, like a word.

Four principles, each load-bearing:

1. **LaTeX is never shown uninvited.** It remains the storage format and the
   power-user escape hatch, behind one `LaTeX` toggle (the Advanced fold of
   the year-10 rule). The current source editor becomes that fold — it is
   not deleted, it is demoted.
2. **Everything findable by eye, everything fast by fingers.** Every symbol is
   reachable by mouse through a named, searchable palette; every palette
   tooltip shows the type-it-yourself route, so the palette *teaches* the
   keyboard (spec 12 §4's principle, kept).
3. **What the palette offers always renders.** The inventory is a subset of
   what `flutter_math_fork` + `latex_compat` proved they can draw; a generated
   test walks every palette row and fails if any falls back. A student can be
   handed an error only by *imported* or *hand-written* LaTeX — never by our
   own buttons.
4. **An equation is text.** It lives in the sentence, moves with it, selects,
   copies (as LaTeX, so it pastes into anything), and undoes like the
   characters around it.

below is data, not code: one table (JSON) drives the palette, the search

### 4.3 What is deliberately NOT offered

Theorem environments, `\sideset`/`\tag`/`\href` (the renderer cannot draw
them — they stay import-only, falling back visibly), the mhchem chemistry
package, SI-unit typesetting, equation numbering. A search miss says:
*"Openote doesn't have that as a button yet. If you know LaTeX, the LaTeX
view can write anything."* — a pointer, not a dead end.

One bar, appearing **docked to the equation being edited** — under the

**As shipped, the three rows became one**, because that is what a toolbar tab
is here: the shapes inline in their fixed order, then one drop-down gallery
per symbol category (a row cannot hold two hundred symbols and a scrolling
strip of them would be a lucky dip), then the search box, the `= 42` answer
and the LaTeX fold. The rules below all survived the move — fixed positions,
categories, teaching tooltips, plain-words search.

- **Row 1 — structures.** Always the same buttons in the same places; muscle
  memory is the feature. Matrix and accents open small pickers (grid-size
  chooser; accent gallery).
- **Row 2 — symbols.** The Common set inline, then a tab per §4.2 category
  opening a gallery. A **Recently used** cluster grows at the front of this
  row (persisted per workspace).
- **Row 3 — search and the fold.** The search box matches names *and
  aliases* ("power", "to the", "squared" all reach x²; "choose" reaches nCr;
  "roughly equal" reaches ≈). Results appear as chips in place of row 2;
  Enter inserts the first. The `LaTeX` toggle at the end is the Advanced
  fold: today's source editor, verbatim, round-tripping with the visual view.
- Every button: hover tooltip = *name* + *type-it-yourself route* where one

### 5.3 Inside the equation

Empty boxes render as small dotted squares (▢, ~1ch), the **active** box
tinted with the accent colour. Boxes you leave empty stay visible wherever
the equation shows — they are unfinished work, not errors — and export as
the same small square (what you see is what prints, matching OneNote).

## 6. Interactions — to the keystroke

All new bindings are rows in `ui/keyboard_map.dart` first (the v0.16 rule:
a binding that isn't in the table doesn't exist), so Ctrl+/ documents them
for free.

| Keys | Where | Does |
|---|---|---|
| Alt+= | in text | start an equation at the caret; inside one, finish it |
| Esc | in an equation | finish; caret lands after the equation |
| Tab / Shift+Tab | in an equation | next / previous empty box |
| ← → | in an equation | walk the equation; step **into** structures at their edge, not over them |
| ↑ ↓ | in an equation | between a structure's levels: numerator↔denominator, upper↔lower limit |
| Space | in an equation | build what you just typed (§6.2); otherwise a thin space |
| Backspace | in an equation | at a structure's edge: **unbuild** it — the bar disappears, `1/2` comes back as characters; inside: delete a character |
| Enter | display equation | new row (aligned) |
| Enter | inline equation | finish the equation and continue the sentence (Q4) |
| Ctrl+= / Ctrl+Shift+= | in an equation | index box / power box — the same chord that does sub/superscript in text |

### 6.1 Entering and leaving

Alt+= drops an equation *chip* at the caret and opens it. Clicking any
rendered equation while editing text puts the caret **inside it** in one
click (Q2); clicking in view mode does nothing special, as now. Leaving
(Esc, click elsewhere, arrow off either end) commits — there is no separate
save, and an equation left completely empty removes itself (the existing
F-3 rule, kept).

### 6.2 Typing — the build-up rules (spec 12 §3, now in place)

- **Space and operators build.** `1/2` + space → ½. `x^2` + `+` → x² with
  the + after it. The not-yet-built tail stays visible as plain characters
  at the caret — typing is never blocked by an incomplete construct.
- `/` builds a fraction from the token before it; `(…)/(…)` groups; `^` and
  `_` open raised/lowered boxes; `sqrt`+space, Greek names, function names,
  `<=` `>=` `!=` `->` `oo` autocorrect from the same table the palette reads.
- Function names (sin, cos, log…) go upright automatically; single letters
  stay italic. This is the rule students' textbooks follow, applied silently.
- Unparseable input **never blocks and never errors**: it stays as typed
  characters until it parses, exactly as spec 12 §3.3 requires.

### 6.3 Deleting — never eat what the student typed

Backspace at a built structure's boundary **unbuilds** it back to its linear
characters (spec 12 §2's round-trip guarantee: every built form unbuilds to a
string that rebuilds identically). Backspace never silently deletes a whole
fraction; Delete on a *selected* structure removes it whole. Deleting one of
a bracket pair unbuilds the pair to plain characters rather than leaving a
mismatched grower.

### 6.4 Selection, copy, paste

Selection is box-aware: dragging or Shift+→ across a structure's edge takes
the whole structure. Copy puts LaTeX on the clipboard (pastes into Word,
Overleaf, ChatGPT, anything); paste *into* an equation parses LaTeX or linear
input through the same grammar; within Openote the equation travels intact
with the copy/paste round-trip that all blocks already use.

### 6.5 Undo

One undo step per build event (a build-up, an unbuild, a palette insert) and
per burst of typed characters — the granularity the text editor already
uses, wired into the page's single undo stack. Undo of a build-up restores
the linear characters, not an empty equation.

### 6.6 Errors

The palette cannot produce one (§3, principle 3). Equations arriving from
import or the LaTeX fold that the renderer cannot draw open **in the LaTeX
fold** with the existing plain-words notice — the visual editor never shows
a construct it would corrupt on the next edit.

### 6.7 The dollar guard

Adopt Pandoc's rule for `$…$`: the opening `$` must be followed by a
non-space, the closing `$` preceded by a non-space **and not followed by a
digit**. The measured offender in §2 (`"$5 and lunch is $"`) fails both
halves and stays a sentence about lunch. This is a small, self-contained
grammar fix with its own test and can ship ahead of everything else.

## 7. Maths in the sentence

Reading is done (`bbe9d30`): `$…$` draws on the line's own baseline and
grows only that line. This section is about *editing*.

**The model: an equation is one atom in the text.** In the live editor the
`$…$` source region draws as the rendered equation occupying one caret
position (the `_SourceSpan` WidgetSpan trick that images and cards already
use — one code unit visible, full source preserved). Arrow keys step over it
as one thing; Backspace from the right steps *into* it (Q3); click enters it.
An equation never wraps internally — the line wraps before or after it, and
one wider than the box shrinks to fit as block equations already do.

**Editing in place — the one genuinely hard interop.** Flutter's `TextField`
owns every keystroke; a WidgetSpan inside it can never receive input.
Options, with what each cannot do:

| Option | What it cannot do |
|---|---|
| A. True in-TextField structural editing | Receive keystrokes at all — the framework routes input to the field, not the span. Dead end, stated so nobody re-walks it |
| B. **In-place overlay:** entering the equation swaps in the equation editor at exactly the chip's rect, matching font size and baseline; the field keeps the atom; commit writes `$latex$` back into the text run | Perfect pixel continuity during the swap (mitigated by matching metrics — the spike measures the diff) |
| C. Replace the text stack with a custom document editor (the "structured rich-text editor" the ROADMAP already names) | Ship this year. It remains the asymptotic answer; B is designed so its equation engine lifts straight into C |

**Decision: B.** The equation editor is one widget used three ways — the
block, the inline overlay, and (later) C.

**Correction, written after building it.** What shipped is B's *substance*
without B's choreography: clicking an inline equation opens the same
`MathField` and the same maths bar in a small card anchored **under** the
equation, rather than an overlay drawn at exactly the equation's rect. The
equation in the sentence rewrites live as the student types, so nothing is
hidden from them while they work.

The reason is worth keeping. Pixel-matching a `WidgetSpan`'s baseline inside
a `TextField`, across three platforms and two themes, is a lot of fragile
measurement bought purely for a transition effect — and every frame of it is
somewhere the equation can jump. The *editing* is identical either way; only
the choreography is simpler. If the card ever feels disconnected from the
equation, the plan's original overlay is still the better answer and nothing
built here blocks it.

**What made this half non-optional.** Drawing the equation instead of its
source is precisely what stops the caret walking into the middle of it. Ship
the drawing without a way back in and inline maths becomes read-only — a
worse defect than the one being fixed. The click path is not a nicety; it is
the other half of the same change.

Inline ↔ display is one toolbar toggle: inline lifts out to a display
equation on its own line; display tucks back into the sentence at the caret.

## 8. How it is built

### 8.1 The engine

| Option | What it cannot do |
|---|---|
| Extend `linearToLatex` (string in, string out) re-run per keystroke | Hold a caret. A string has no stable notion of "inside the second box"; every structural edit becomes offset archaeology. This is the current architecture and is exactly why nothing builds in place |
| Custom edit tree + **custom layout** (own RenderObjects) | Ship soon. It re-implements flutter_math's box model — thousands of lines of typesetting we already get free, to be maintained forever |
| Adopt simpleclub's `math_keyboard` wholesale | Cover the inventory (it targets mobile school maths, smaller set); desktop keyboard model. Licence and internals worth reading before building — its architecture validates the row below |
| **Edit tree + TeX serialisation per frame** — a small editing AST purpose-built for §4's inventory; every frame serialises tree + caret token + slot tokens to TeX and renders through `OnoteMath` | Precise click-to-caret *inside* an equation in v1 (click enters at the nearest box; Tab/arrows are the precision tools). Sub-token selection highlight in v1 |

**Decision: the last row.** The tree is ours and knows about boxes and
carets; the typesetting stays flutter_math's and never forks.
`linear_math.dart`'s grammar becomes the tree's parser (incremental,
token-boundary triggered) instead of a one-shot transform — the grammar
itself, and spec 12 §3, do not change.

**Spike before Phase 1 commits** (throwaway, measured, results appended
here): (1) serialise+parse+layout latency per keystroke on the imported
piecewise equation and a 3× version of it — target < 8 ms on the dev
machine; (2) a caret token (thin accent-coloured rule) renders at correct
height inside scripts, fractions, roots; (3) `\square` renders as the slot
box in `flutter_math_fork 0.7.x`, else pick the fallback glyph; (4) overlay
baseline continuity — pixel-diff the chip against the overlay at rest.

### Spike results (2026-08-19)

**65 primitives probed against the real renderer; 62 drew, 3 did not.**

| Probe | Result |
|---|---|
| `\square`, `\Box` | drew — the empty box is a real glyph, no fallback needed |
| `\rule{0.07em}{0.9em}` | drew, and at the correct height *inside* a fraction, a superscript and a root, which was the open question |
| `\textcolor{#RRGGBB}`, `\colorbox{#RRGGBB}` | drew — **hex accepted**, so the caret and the active box are theme-coloured through the same rendering path rather than a second one |
| `\rlap`, `\mathrlap`, `\llap` | **all three failed** |
| `\frac{}{2}`, `\sqrt{}` | drew — empty groups are legal, so a half-built equation always renders |
| the other 57 (`\binom`, `\cases`, `\vmatrix`, `\xrightarrow`, `\nmid`, `\rightleftharpoons`, …) | drew |

**Correction to §5.3, forced by the `\rlap` result.** The plan assumed a
zero-width caret was available. It is not: with no overlap primitive the
caret has to be a real 0.07em rule, so the equation shifts by roughly 1.4px
at 20px type as the caret moves through it. Judged acceptable and shipped —
under two pixels, and every alternative was worse (a phantom rule at *every*
gap doubles the TeX and changes operator spacing at the start of a row).

**Correction to §5.3, second half.** An empty box the caret is standing in
does **not** also get a hairline. `\colorbox` cannot hold the rule cleanly,
and a hairline inside an empty square reads as a stray mark anyway; the
tinted accent-coloured box IS the caret there, which is what OneNote does
too. The caret is also **steady, not blinking** — blinking would re-serialise
and re-lay-out the whole equation twice a second to convey nothing the tint
does not already carry.

**(1) latency and (4) overlay baseline were NOT measured**, and neither
decision ended up resting on them. Per keystroke the cost is one string build
plus one `Math.tex` layout — the same layout the old editor already did on
every keystroke, so it cannot be slower than what shipped — and the whole
208-test engine suite runs in about five seconds. The overlay pixel-diff went
moot when §7 changed (see the correction there). Said plainly rather than
quietly dropped: if inline maths ever feels sluggish on a long equation, (1)
is the measurement to take, and nobody has taken it.

### 8.2 What does not change

Storage is untouched: inline `$…$` in the text runs, blocks with
`{'latex', 'linearSource', 'display'}`. The importer keeps emitting what it
emits; Markdown export, git sync, MCP, and the open format never learn this
happened. `latex_compat`, `OnoteMath`, the visible fallback, and the
calculator (`evaluate.dart` — kept, shown as `= 42` at the bar's edge) all
stay. PDF export of inline `$…$` is task #78 and ships inside Phase 2, where
the inline work already has the wiring open.

## 13. The audit, 2026-08-20 — and what it changed

The owner sent a photograph of an integral: `∫ 3x + 5dx` with the 5 and the 2
stacked off to the right instead of on the sign. *"There were a couple other
similar little issues so i want you to go over it all again and make sure its
all looking good and working fine. Also please tidy up the menu bar as its
pretty chaotic at the moment, and spend a bit of time going through and just
adding some really nice QOL features to all the maths stuff."*

Six read-only agents audited a dimension each — serialisation, interaction,
inventory, toolbar, inline, render fidelity — and each finding was then handed
to an adversarial verifier told to REFUTE it by running it. **40 findings
survived.** Two designers then proposed the toolbar and the QOL set from
opposite angles (never-seen-LaTeX, and writes-maths-daily) and a third
synthesised them.

### 13.1 The photograph: two defects, not one

| | |
|---|---|
| `MScript.texOf` braced its base unconditionally | `{\int }_{5}^{2}` is not `\int _{5}^{2}`. Braces make the base an ORDINARY atom, and TeX only stacks limits on a BIG OPERATOR — so the limits slid out beside the sign the way indices sit beside a variable. Every n-ary was hit |
| `tab()` returned false with no boxes left | After both limits there was nowhere to go, so the integrand was typed into the exponent: `{\int }_{5}^{23x+5dx}`. A structure you cannot leave by the key that got you into it is a trap |

### 13.2 The family behind "a couple other similar little issues"

Every one of these was a **silent** failure: the equation stopped drawing and
became a grey box of source, or — worse — drew something that was not what the
student typed.

| Typed | Stored | What happened |
|---|---|---|
| `20%` | `20%` | `%` is TeX's COMMENT character. Drew as `20`. `30%+2` drew as `30`. **Nothing said anything had gone.** |
| `{1,2,3}` | `{1,2,3}` | Balanced braces are TeX grouping, so the braces were simply invisible — measured byte-identical in width to `1,2,3` |
| `a{b`, `a$b`, `a#b`, `a&b` | verbatim | Undrawable. And unbalanced braces make the whole equation un-re-openable, so the student is dropped into the raw LaTeX view next time they click in |
| `50% off` in a words box | `\text{50% off}` | Undrawable. `_escapeText` also *replaced* `{` with `(`, so the box quietly said something else |
| `x²` then ° or a prime | `x^{2}^\circ` | Double superscript — TeX refuses it outright |
| `30` ° `C` | `30^\circC` | The `C` ran into the command name |
| Backspace on an empty power | `^` | Not drawable TeX at all |
| `x^(n+1)` after Backspace | as written | Re-read as TeX, so the script took only the bracket |
| Backspace at a matrix edge | `1234` | One keypress flattened a filled 2×2 grid |
| `x < -3` | `x ← 3` | The `<-` shortcut fired on an ordinary inequality, and the space between could not stop it because a space that builds nothing inserts no atom |

**The fix is one layer, not ten patches.** `_emit` escapes every character TeX
reserves, `_escapeText` does the same for text mode with its own table
(`\backslash` and `\sim` are maths-only and fall back inside `\text{}` —
probed), and `rowToTex` puts an empty group between two atoms that would
otherwise form a double script. `math_tex_safety_test.dart` is the standing
guard: it renders what the editor *produces*, not what we thought it would.

### 13.3 Backspace changed model — a correction to §6.3

§6.3 promised Backspace would "unbuild" a structure into the characters that
made it. That read well and was wrong three measured ways (the bare `^`, the
`x^(n+1)` misrender, the flattened matrix). **Backspace at a structure's right
edge now steps INSIDE it, at the end**, which is what every other equation
editor does; deleting off the front unwraps, keeping the contents; a structure
already empty is removed outright. The promise §6.3 was written to keep —
nothing the student typed is ever destroyed — holds better under the new rule
than it did under the old one.

### 13.4 The toolbar, round three

Round two measured **1725–2230 px** against a default window of **1280**, with
no scrollbar and a mouse wheel that did nothing, so the search box, the answer
and the LaTeX escape hatch were off the edge. Twenty-seven controls; eighteen
ragged-width shape chips in a flat run; eight word-labelled drop-downs costing
1010 px between them; and every gallery one symbol per row — Greek was a
1119 px column, because **a `Container` with an `alignment` expands to fill its
loose constraints**.

Now twelve controls, measured under 900 px:

```
 ½  x²  √  Σ  ∫  (□)  {cases  [matrix]  │  ⊞ More shapes ▾  Ω Symbols ▾  │  = 0.5   ⋯
```

- Eight shapes stay, chosen by what a student reaches for in an afternoon.
- One **Symbols** door with the search at the top of it and the categories
  stacked inside — eight doors made the student guess which category `≅` was
  filed under; one panel answers the guess instead of posing it.
- The answer sits in a **fixed-width slot**, so the row no longer slides
  30–177 px sideways as it appears.
- Every chip is one size, so the row is not ragged and the galleries are grids.
- The whole toolbar scrolls and takes a mouse wheel — measured on Insert too
  (1217 px against 965), so that fix is every tab's.

### 13.5 Quality of life

| What | Why it mattered |
|---|---|
| **Undo takes back a keystroke** | It used to take exactly one undo point per editing session, so Ctrl+Z after a typo took back the whole equation *and its block*. Now coalesced at 700 ms, on the page's existing stack — two undo stacks means two chances to disagree about which one Ctrl+Z belongs to |
| **Every shape has a keyboard route** | Nineteen of them had none, so the only way to a matrix was the mouse. This is what makes moving twelve chips off the row honest — they are all *faster* from the keyboard than they ever were from it |
| **Search finds what you call it** | A name now outranks another row's loose alias ("angle" found ° before ∠; Enter inserts the first hit, so the student got the wrong symbol *in* their equation), and a query longer than the stored name matches ("greater than or equal to" scored zero and the panel said it did not exist) |
| **Recently used** | Twelve, newest first, at the top of the symbol panel — never inline, because a chip that changes identity under the pointer is worse than no shortcut |
| **The answer is clickable** | `= 0.5` writes itself into the equation. A calculator OneNote paywalls |
| **Click to place the caret** | Clicking an equation you are already in puts the caret at the end. True hit-testing needs box geometry the renderer does not expose; predictable beats mysterious, and it used to do nothing at all |
| **The caret stops growing** | It was sized in `em`, which is measured against the font size where it sits, so it grew 2.9× too tall nested inside a script of a script. `ex` tracks the x-height |
| **The active box is visible** | `\colorbox` draws its contents and never paints its fill in flutter_math_fork 0.7.4 — the "you are here" tint has been invisible since it shipped. `\fcolorbox` paints |
| **An empty words box is visible** | It drew 0 px, so pressing the button was pixel-identical to not pressing it |
| **Delete takes one character** | It used to take an entire words box, and everything written in it, on one keypress |

### 13.6 Confirmed and NOT done

Honest list, all verified, none fixed here — they are the next round, tracked
as task #83:

- **Inline:** emptying an equation in the click-in card then typing again eats
  the words after it; tapping one throws `ArgumentError` below 436 px of
  window; there is still no way to *create* an inline equation except typing
  `$…$` (Alt+= makes a block and cuts the selected words out of the sentence);
  an equation inside bold renders as raw LaTeX; one in a table cell reverts to
  raw `$x^2$` when read; flashcard lines cannot hold maths at all.
- **Selection** inside an equation does not exist (Shift+arrow does what arrow
  does), and Ctrl+C copies the whole block while **Ctrl+X cuts it**.
- **Accessibility:** the field and every palette chip are unlabelled, so a
  screen reader gets silence.
- **Matrix editing:** no way to add a column or delete a row.
- **Per-keystroke latency** still unmeasured — v0.18 §8.1's spike item (1),
  now outstanding for a second round.
