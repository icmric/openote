# v0.16 — Full keyboard control

> PLANNING.md accessibility: "full keyboard control". Design-first, like
> the MCP work (spec 14): the deliverable is not fifty bindings but ONE MAP
> with a consistency rule, so every future surface ships keyboard-complete
> instead of keyboard-someday.
>
> Status: phases 1–4 SHIPPED. `ui/keyboard_map.dart` is the table,
> `ui/shortcut_overlay.dart` renders it on Ctrl+/ (View tab has a button
> too), and the canvas traverses: Tab/Shift+Tab in reading order (the
> export's y-then-x sort — THE order), arrows spatially, Enter into the
> block's editor, Ctrl+arrows nudge (grid step; +Shift = 1 px), Escape
> climbs back out. `keyboard_map_test.dart` pins phases 1–2 from the real
> shell; `keyboard_regions_test.dart` and `keyboard_board_test.dart` pin
> 3–4. i18n (§5) is the remaining item, still waiting on the
> which-languages decision.
>
> What phases 3–4 added, and the two things they found:
> **F6 / Shift+F6** cycles sidebar → toolbar → page → open panel, with a
> ring around the region you are in that clears on the next click. It is
> the ONLY keyboard route to the toolbar or a panel — the canvas binds Tab
> to block traversal so Tab never leaves the page, and `_canvasFocus` is
> `skipTraversal` so it cannot come back. Everything in the toolbar was
> always focusable; it was simply unreachable. F6 enters a panel's BODY,
> never its header, because landing on Close means the first Space a
> student presses in the study panel shuts the panel.
> **The board** walks its cards on arrows, carries them on Ctrl+arrows,
> edits on Enter and deletes on Delete — on its own focus node, so the
> canvas's identical bindings stand down while it holds the keyboard.
> **Found while auditing:** Escape in the shell's ladder had no
> `_routeOnTop` guard, so one Escape aimed at a dialog also toggled find
> off and unfocused the dialog's own field behind it; and the find bar's
> Enter arrived as `TextInputAction.done`, which unfocuses the field, so a
> SECOND Enter did nothing at all. Both fixed.
>
> Two framework facts phase 2 established, for whoever touches this next:
> a `HardwareKeyboard` handler returning true does NOT stop the
> framework's own `Shortcuts` — consuming arrows globally left Flutter's
> directional focus walk running in parallel until focus crept into the
> sidebar search box. And an unclaimed Ctrl+arrow over a focused subtree
> falls through to the default `ScrollAction`, which asserts when two
> primary scrollables exist. Both are why traversal lives in the canvas's
> own `Shortcuts`/`Actions` behind a `FocusNode` (autofocus, refocused on
> canvas pointer-down and on Escape-out-of-editor): nearest-ancestor wins,
> and dialogs/text fields opt out for free by holding focus themselves.

## 1. The consistency rule

**The keyboard map lives in code as a single table** (`ui/keyboard_map.dart`,
to be created): every binding as data — key, context, action, description.
Two consumers keep it honest:

1. The app registers its `Shortcuts`/`Actions` FROM the table — a binding
   that isn't in the table doesn't exist.
2. A **shortcut reference overlay** (`Ctrl+/`) renders the table, so the
   documentation is the implementation and cannot drift.

The rule for future features, mirroring spec 14 §7: a PR that adds an
interactive surface adds its rows to the table, or it isn't done. A test
asserts every registered shortcut has a description.

## 2. Inventory (done — what exists and where it lives)

Every binding found by the grep is now a row in `ui/keyboard_map.dart`.
The implementation sites, for the phase that moves registration into the
table: the global chords live in `app_shell.dart`'s HardwareKeyboard
handler (deliberately NOT widget-tree `Shortcuts` — see the comment there:
bare-letter activators shadow text fields on desktop); per-surface
bindings live in `table_block_view.dart` (cell movement `Shortcuts`),
`code_block_view.dart` (Ctrl+Enter run, Tab-as-spaces via focus onKey),
`study_panel.dart` (Space/1–4 via focus onKey), `unicode_input.dart`
(Alt+X chord test), `sidebar.dart` (rename Escape). Editor-internal and
staying that way: the markdown engine's list/fence continuation and
`wrap_selection.dart`'s wrap-on-pair-char (documented in the map as a
behaviour, not a chord).

## 3. The map to build toward (proposed)

| Context | Key | Action |
|---|---|---|
| Everywhere | `Ctrl+/` | Shortcut reference overlay |
| Everywhere | `F6` / `Shift+F6` | Cycle focus: sidebar → page → open panel |
| Canvas | `Tab` / `Shift+Tab` | Select next / previous block (reading order) |
| Canvas | `Enter` | Edit the selected block (its natural editor) |
| Canvas | `Escape` | Exit edit → deselect → close panel, in that order |
| Canvas | Arrows | Move selection spatially between blocks |
| Canvas | `Ctrl+Arrows` | Nudge the selected block |
| Sidebar | Arrows / `Enter` | Move through pages / open |
| Board block | Arrows / `Enter` / `Ctrl+Arrows` | Move between cards / edit / move card between columns |
| Dialogs | `Enter` / `Escape` | Confirm / dismiss (audit: every dialog) |

Screen-reader semantics ride along: the same traversal order feeds
`FocusTraversalGroup`s, so fixing Tab fixes assistive tech ordering too.

## 4. Phases

1. ~~**Inventory + table + Ctrl+/ overlay**~~ — SHIPPED. No behaviour
   change, ends the era of undiscoverable bindings.
2. ~~**Block traversal core**~~ — SHIPPED (Tab/Enter/Escape/arrows on the
   canvas); a canvas you can work one-handed.
3. ~~**Region cycling + dialog audit**~~ — SHIPPED. F6 above; the audit's
   fixes were: Escape now cancels the update notice and the media-copy
   dialog (both had `barrierDismissible: false`, which switches the
   framework's Escape handling off entirely), Enter now confirms "Remind
   me" and the exam date, and Ctrl+Enter saves a flashcard whose fields
   are multi-line and so can never carry a plain Enter.
   **Still un-dismissable, deliberately:** the three progress modals
   (PDF import, notebook repair, OneNote import) have no cancel to route
   Escape to, and they pop themselves when the work ends — giving them a
   dismiss key would hide a running job with no way back to it. If any of
   them grows a Cancel, it must grow an Escape with it.
4. ~~**Board & panel internals**~~ — SHIPPED. Board above; the PDF reader
   already had pdfrx's full key set and only needed its focus node to
   autofocus; the find bar gained Shift+Enter; F6 reaches panel bodies.
   **Not done:** arrow-key row navigation inside the tags/outline/links
   panels and the sidebar tree — Tab reaches every row once F6 puts you
   in the region, so these are an improvement, not a hole. The sidebar
   still has no keyboard rename, context menu or reorder.
   The every-new-surface rule now enforces itself via §1.

## 5. After this: i18n (the third of the trio, in order)

Wiring `flutter_localizations` + ARB extraction is mechanical but touches
every string in the app — it gets its own pass after keyboard, with one
decision from Eric first: which languages have an actual audience, because
the infrastructure is cheap once and translations are a commitment forever.
