# Openote v0.3 — the student release plan

> **Document status:** Draft v0.1 · Planning · 2026-08-03
> **Owner:** Eric · **Related:** [v0.2 release plan](v0.2-release-plan.md) (its carried-verification list applies) · [ROADMAP](../../ROADMAP.md) · [PRD](../02-product-requirements.md) · [Vision §6 personas](../00-product-vision.md)
> **Sizes:** **S** ≈ hours · **M** ≈ 1–3 days · **L** ≈ ~a week · **XL** ≈ multi-week, for one developer with AI sessions.

## 1. The strategic reframe

The primary demographic is **students**. That sharpens the vision's three personas into one person: someone who sits in lectures, annotates slides, writes equations, photographs whiteboards, revises for exams, shares notes with classmates, and owns a mix of a laptop and (maybe) a tablet.

The uncomfortable truth this plan is built on: **"OneNote, but open source" is not a reason for most students to switch.** Openness and Linux support win us the enthusiast minority. To win ordinary students, two things must both be true:

1. **Parity where it hurts** — every high-frequency thing OneNote does must work, because a student who hits a missing basic in week one goes back.
2. **A study advantage OneNote cannot match** — features that measurably help *studying*, not just note-keeping. OneNote is a filing cabinet; the wedge is to be the notebook that actively helps you learn from what you wrote.

**Proposed headline for 0.3:** *"Annotate your lecture slides. Tag what matters. Your revision cards make themselves."*

Every differentiator below is chosen against one test: *does this help a student the week before an exam?*

## 3. Parity — what a switching student still hits

## 4. The leg up — student differentiators

Each entry: the pitch in one sentence a student would repeat to a friend, why OneNote can't easily match it, and honest cost.

### D1 — PDF lecture-slide annotation ⭐ *the flagship*

> "Drop the lecture PDF in, write on the slides with your pen, and search the slide text later."

This is the workflow GoodNotes and Notability built businesses on, and it is **Apple-locked and paid** there. OneNote's equivalent ("Insert → PDF printout") rasterises pages into blurry images, slowly, and loses the text. Nobody serves this well on Windows/Linux, and it composes perfectly with what we have: each PDF page becomes a locked background image block on its own Openote page (or stacked on one canvas), ink rides on top exactly as it already does, and the extracted text layer feeds the existing notebook-wide search.

- **Step 1 (spike, S):** PDF rendering. The realistic engine is **pdfium** (BSD-licensed, the Chrome PDF engine). Options: `pdfrx`/`pdfium_bindings` packages, or our own thin FFI in the Rust core (`pdfium-render` crate — but pdfium itself is a prebuilt native binary per platform, ~5 MB; the release workflow must bundle it). Licence-audit whatever we pick.
- **Step 2 (M):** Import flow — "Insert → PDF as pages": render each page at 2× into a content-addressed blob, one Openote page per PDF page (title = `Slides p.3`), background-locked so the eraser/lasso never grab it.
- **Step 3 (M):** Text layer — pdfium text extraction per page stored as hidden `content['sourceText']`, indexed by the existing brute-force search; snippets label themselves "in slide text".
- **Step 4 (M, later):** Re-export annotated PDF (original pages + our ink as vector overlay) for submission/sharing.
- **Total: L–XL**, cleanly staged; steps 1–3 are the 0.3 cut.
- **Risk:** pdfium binary distribution across three OSes (and later Android). The spike answers it before anything else is built.

### D2 — Flashcards from your own notes ⭐ *the study loop*

> "Tag a line as Question or Definition while you take notes; the week before the exam, Openote quizzes you on them."

We accidentally built the on-ramp already: **Question** and **Definition** tags exist, in the gutter, with a rollup panel. The step from "find tags" to "study tags" is small and *no mainstream notes app does it natively* — students maintain a painful second system (Anki/Quizlet) by hand. OneNote structurally can't follow quickly: it has no per-line tag rollup UX this clean and no incentive to cannibalise nothing (there's no Microsoft flashcard product tied to OneNote).

- **Card sources (S–M):** a tagged **Question** line → front; the following indented lines (or rest of the block) → back. A tagged **Definition** line with `term — meaning` or `term: meaning` splits into both directions. `==highlight==` inside a tagged line becomes a cloze deletion.
- **Review mode (M):** a Study panel: deck = current section or notebook, flip-card UI, again/hard/good/easy, **SM-2 scheduling** persisted in workspace settings keyed `notebook:block:line` (survives sync because tags travel with blocks).
- **Anki export (M):** `.apkg` is a zip containing a SQLite database — **we already ship SQLite**; no new dependency. CSV as the trivial fallback. This defuses "but my cards live in Anki": we feed Anki instead of fighting it.
- **Total: L**, partitionable; export alone is a shippable first slice.
- **Scope guard:** this is *reviewing your own notes*, not a flashcard authoring suite. No images-on-cards v1, no shared decks.

### D3 — Math that computes, free

> "OneNote charges your university for math answers. Openote's is free."

OneNote paywalls equation *solving* behind M365 Education subscriptions. We own the linear-math grammar end to end, so **numeric evaluation** of what a student typed is cheap: type `= ` after an expression (or press a button on a math block) → evaluate arithmetic, powers, roots, trig/log, constants, unit-less fractions → append the result. No CAS, no steps, no symbolic algebra in v1 — the honest 80% for first-year problem sets at ~5% of a CAS's cost.

- Evaluator over our existing linear AST in Dart (or Rust, shared with a future CAS), M. Errors show inline and never block rendering.
- The vision's "math evaluation / CAS" future item gets its first concrete step without violating the non-goal ("we do not commit to *solving* them" — evaluation of arithmetic is a calculator, not a solver).
- **Total: M.**

### D4 — Group notebooks over any shared folder *(mostly already true)*

> "Put the notebook in your group's shared Drive folder. Everyone's edits merge. No accounts."

The sync design already makes this structurally work: each member's device appends only its own log, so a shared folder gives N-writer merge with zero conflict dialogs. What's missing is honesty and polish, not architecture: a "Share this notebook…" flow that moves the `.onotebook` into a chosen folder and explains the model; a visible "N people / last pull" surface; auto-pull on window focus (removing the manual click); and a documented caveat that simultaneous edits to the *same paragraph* resolve last-writer-wins until the CRDT lands.

- **Total: M** — extraordinary value for the size, and a genuine "OneNote needs accounts and OneDrive; we need a folder" story. Also the forcing function for the auto-pull (file-watcher) work sync needs anyway.

### D5 — Audio recording pinned to your notes *(the Notability feature)*

> "Record the lecture; tap a line to hear what the lecturer was saying when you wrote it."

Deferred in the PRD (MEDIA-5), but for the student demographic it is a top-three request and OneNote's own version is Windows-only and poor. Requires: recording (a maintained package or platform channels — dependency-light options need auditing), timestamps on block/stroke creation (we already store `strokeStart` and `updatedAt` — most of the correlation data exists), playback with tap-a-block-to-seek, audio blobs in the content-addressed store (sync rides free; large-file caveats to document).

- **Total: L.** Recommended as the *second* flagship, after D1 proves the heavy-asset pipeline (blobs, size, sync) on PDFs.

### D6 — OCR: search your photos *(investigate, then decide)*

> "Search finds the whiteboard photo from week 3."

Composes with P2 (JPEG import) and D1's hidden-text pattern. The engine question decides everything: platform OCR (Windows `Windows.Media.Ocr`, macOS Vision) is free and good but per-platform FFI work and leaves Linux out; Tesseract is cross-platform but heavy (native lib + language data) and mediocre on handwriting. **Spike S, decision after.** Not committed for 0.3.

### D7 — Android tablet build *(reach)*

> "OneNote-grade pen notes on the cheap tablet you actually own."

Flutter makes it plausible; the real costs are Rust-on-Android (NDK build wiring in CI), storage/permissions, and a top-toolbar-on-touch UX pass. The student market on Android tablets is underserved (GoodNotes is iPad-first; OneNote Android is weak). **Total: L–XL, beta target.** iOS stays blocked (AGPL/App Store conflict + no Apple account) — recorded, not forgotten.

## 5. Recommended shape of v0.3

Three phases, each independently shippable; the release can cut after any of them.

**Phase A — "no reason left to go back" (parity sprint):**
P1 paste/drag-drop → P2 JPEG import → P3 hyperlinks → P4 vector PDF export → P5 reorder → P8 find-replace → U1 suggestions → U2 tag chords → U3 copy-link → U5 fences → P7 guides → P6 resize → P9 lasso. (Roughly 3–4 weeks of focused work; front-loaded with the daily-frequency items.)

**Phase B — the flagship:** D1 PDF slide annotation, steps 1–3. This is the feature the release is named for.

**Phase C — the study loop:** D2 flashcards (export slice first, then review mode) + D3 math evaluation + D4 group-notebook polish.

**Stretch (only if C lands early):** D5 audio, D6 OCR spike, P10/P11 importer round (needs your tagged-`.one` fixture), U8 a11y pass.

**Explicitly not in 0.3:** live embeds (still the 0.4 flagship candidate — it composes beautifully with D1/D2 but must not dilute this release), real-time collaboration, Loro/structured text model (unless paragraph-collapse demand forces it), iOS, web clipper, ink recognition, any AI feature, task-manager creep (due-date/agenda views were considered and **cut** — a date on a tag is a slippery slope into a planner; revisit only on real user demand).

## 6. What "nailing OneNote" means as a bar

A concrete acceptance test for the parity claim, student edition — run it before calling Phase A done:

1. Screenshot a slide → paste it into a page → write on it in pen → move both together. *(P1, existing ink)*
2. Import a real student `.onepkg` containing phone photos → the photos are there. *(P2)*
3. Ctrl+1 a line during a lecture; find it in Find Tags that evening. *(U2, existing)*
4. Export a handwritten+typed page to PDF; a classmate searches text in it. *(P4)*
5. Reorder a semester's pages by dragging; nothing mis-nests. *(P5)*
6. Misspell "definately"; right-click; fix it. *(U1)*
