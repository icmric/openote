## 2. Engineering debt

### 2.1 Run the builds we ship · **S**

CI builds Windows, macOS and Linux on every push, and **nobody has used two of
them**. At minimum: launch each, import a PDF (pdfium is a per-platform native
binary and the only dependency that can fail differently per OS), draw, sync a
notebook between two of them.

Cheap, and it is the difference between "we support Linux" being a claim and a
fact.

### 2.2 Split `AppState` · **M**

**`app/lib/state/app_state.dart` is 5,901 lines.** The `StudyState` extraction on
2026-08-04 took it from 3,183 to 2,788; everything since — MCP, code cells, the
board, the planner, keyboard control, git sync, update-through-app — has landed
back in it. It is now larger than before the split, which means the split did not
change the gradient, only the intercept.

`notifyListeners` still offers a rebuild of everything to every listener, which
is why there are per-keystroke caches (deck, sync status, device count) instead
of narrower notifications.

**What worked, and is the template:** `StudyState` succeeded because study
*observes* the document. Its seam is `StudyDocument`, a read-only interface of
eight getters `AppState` already satisfied, so the compiler enforced it.
`PlannerState` (999 lines) went the same way.

**What was deliberately left, and why it is still true:** `SyncCoordinator` and
`TagOps` **mutate** the document — sync calls `reloadNodes()`, `flushSave()` and
`_loadNotebook()`; tags call `pushUndo()`, `updateBlock()`, `markDirty()`.
Extracting either means inventing a *command* interface back into `AppState`,
which is a wider and much less checkable seam. For sync there is a second reason
and it is the deciding one: **its failures are two-device failures**, and every
sync bug this project has found came from use rather than from tests. Refactoring
it without two machines to exercise it is a bad trade.

**So the next cut is neither of those.** Look instead for the clusters that
*observe*: the canvas/view state, the chrome/panel flags, and the find/search
state are all candidates with read-only seams.

### 2.3 Demote the container · **M–L** — now unblocked

The remaining half of [ADR-0006 §3](../adr/ADR-0006-sync-transport-and-text-model.md):
the `.onote` is meant to be a local cache that is never synced. Today the first
device's container still sits in the synced folder being re-uploaded after every
save, and it is **double-clickable on the second machine** — the
two-writers-on-one-WAL-database case the joining flow exists to avoid.

**The blocker recorded here on 2026-08-05 has been retired.** It read: *"take the
container out of the synced folder and a second device has nothing to join;
rebuild-from-log has never been the user-facing join path."* That is no longer
true. **Joining from a git address is exactly rebuild-from-log**:
`adoptLogDirectory` creates a deliberately empty container and the first
`syncPull` materialises every node and page into it. It is covered by
`git_join_test.dart`, `git_join_repro_test.dart` and
`git_join_existing_notebook_test.dart`.

What that work also proved is how much was wrong with it — six defects, each of
which alone produced an empty notebook (Appendix A). So the honest position is
not "unblocked, go" but **"unblocked, and now we know what to check"**: the
verification that was never done has been done once, on the join path, by test.
Doing it on a real notebook between two real machines is §2.1's job and should
come first.

Design for this and the next item: [ADR-0007](../adr/ADR-0007-blob-lifecycle.md).

### 2.4 Blob garbage collection · **M**

**Nothing has ever deleted a blob**, and images and PDFs are still stored twice —
`media_store.dart` says so in its own opening comment: they "go into the `blobs`
table, get mirrored into `.onotebook/blobs/`". Delete a page, empty the recycle
bin, and its pictures stay in both stores for good.

Two things have improved since this was first written and the entry should not
claim otherwise. **PDFs are stored once** and rendered on demand rather than as
one 2× raster per page, and **video never enters `blobs` at all** — it lives as a
file under `.onotebook/media/`. The "~240 MB per PDF import" figure that used to
head this item is obsolete.

What remains is unbounded growth, which audio (§4.2) would make acute.

GC is subtle enough to deserve its ADR: a blob is referenced by pages, by history
snapshots, **and by other devices' logs that may not have synced yet** —
[ADR-0007](../adr/ADR-0007-blob-lifecycle.md) covers why reference counting and
collect-on-delete are both wrong, and how a grace period substitutes for the
handshake the transport deliberately does not have.

## 3. Cheap product wins

### 3.1 Dark slides · **S**

Students annotate at night, and a white 2× slide raster in a dark room is a
flashlight. An invert/dim toggle on locked background blocks is a colour filter,
not a re-render.

### 3.2 Page thumbnails for slide sections · **S–M**

A 60-slide printout is navigated by eye; the outline panel is text-only.
Thumbnails for pages whose first block is a locked background image would make an
imported deck navigable. Cheap, because the render already exists as a blob.

### 3.3 Group / ungroup · **M**

The last piece of CANVAS-7. Alignment guides, corner resize and lasso recolour
all shipped; grouping did not.

### 3.4 HTML export · **M**

The other half of OPEN-7, and the only export a phone reads losslessly. Linkable,
unlike PDF. The vector-PDF work established the pattern: walk the blocks, emit
per type, keep the text as text.

## 4. Structural

### 4.1 The spreadsheet engine · **L**

Eric's second-highest raw ask, and the one most often misdiagnosed as an importer
bug. From [PLANNING.md](../../PLANNING.md): *"it seems to have imported it just as
a plain text table."*

**It is not an import gap.** CSV/TSV/XLSX import already works and lands *values*
— a formula cell imports the number you saw. Keeping formulas live, conditional
styling and charts has nowhere to land: **the table block has no formula model,
no cell styling and no chart to import into.** So the order is decide what a table
block can hold, then the importer fills it, then live data (via the API) and
charts follow. Doing the importer first would produce a second format nobody can
edit.

### 4.2 Audio recording pinned to notes · **L–XL**

> "Record the lecture. Tap any line later and hear what was being said when you
> wrote it."

The Notability feature, and for lecture-goers arguably a bigger draw than
flashcards — it rescues the notes you took badly because you were listening.
Nobody serves it on Windows or Linux.

Recording is the easy part. The work is **timestamp ↔ block correlation** (every
edit already carries `updatedAt`, so the mapping is nearly free *if* recorded at
edit granularity), what happens when a note is edited after the recording, and
the size story — an hour of AAC is ~30 MB per lecture, permanently, which is why
§2.4 comes first.

`media_store.dart` already exists for exactly this shape of file (video today,
audio the same), so the storage half has a home.

### 4.3 OCR on images · **L**

Whiteboard photos and JPEG-imported worksheets are invisible to search.
**The integration half is already built**: PDF import stores a hidden text layer
in `content['sourceText']` and the existing search indexes it, so OCR is purely
additive — run Tesseract via the Rust core (offline, licence-clean) over image
blobs in the background and write into the same field.

### 4.4 The structured `nodes` text model · **XL**

Storage is still an interim Markdown string (`OnoteTextEditor.textStorageKey`
returns `'text'`). Gates per-run styling, paragraph collapse, and per-character
merge for real-time co-editing. Driven by sync rather than by the editor —
[ADR-0006 §4](../adr/ADR-0006-sync-transport-and-text-model.md). The migration has
one landing site by design: `serialize`/`deserialize` behind the ADR-0004 seam.

## 5. Deliberately not yet

Recorded with reasons so they are not re-proposed each round.

- **Android / tablet.** Not "the same app on a smaller screen": the sync
  transport is a *folder*, and Android's scoped storage / SAF makes that a new
  storage backend. A port today would also inherit §2.3 and §2.4.
- **Ink-to-math / handwriting recognition.** High appeal, XL cost, no foundation
  in the current recognition surface. Revisit when the study loop has usage
  evidence.
- **Real-time co-editing.** The op log makes it a transport swap *later*.
  Shared-folder and git group notebooks already cover the group-study case
  students actually have, and per-character merge needs §4.4 first.
- **A first-party sync service.** Contradicts the "point it at a folder or a repo
  you already have" position that makes self-hosting trivial. Only if users ask.
- **PPTX rendering.** A `.pptx` lands as a plain attachment. Rendering needs a
  converter on import or an export-to-PDF step first; the PDF half of the ask
  shipped as card import.

## Appendix A — the git join that produced an empty notebook

Kept because the *dead ends* are worth more than the fix. Reported as: *"it got to
the first step, it even created the notebook, but after several minutes it still
hadnt imported any pages and had made no further progress."*

`git_join_test.dart` passed throughout. It only ever joined a notebook **created
inside the test**; every defect was on the path of joining a notebook someone
**already had**. Six causes, each of which alone produces an empty notebook:

1. **No page-content backfill.** Two backfills existed — nodes and blob bytes —
   and none for blocks. Ops are only written at the moment of a mutation, so
   every page written before a notebook was shared was invisible to the log.
2. **A deleted page rolled back the entire pull.** Pages were written for every id
   the ops mentioned, including deleted ones whose node row is deliberately not
   written → `page_mirror` foreign key → and the pull is ONE transaction, so one
   dead page discarded every page.
3. **A deleted section orphaned its pages** — the same foreign key one level up,
   because `deleteNode` recorded one op for a whole subtree.
4. **…but a parent that was merely never recorded had to be rescued, not
   dropped.** Logs are permanent, so repositories from older builds exist for
   good. The materializer now tracks *purged* ids to tell the two apart.
5. **The push raced the backfills**, and the recorder decided whether to back-fill
   at *open* time — so a warm started before sharing installed with it off.
   Decided at **install** time now, so no caller has to say it twice.
6. **Any failure looked like a hang.** `joinNotebookFromGit` documented "never
   throws" and only guarded the clone; the dialog cleared its busy flag on one
   branch only. A constraint error hundreds of lines away presented as a spinner
   with Cancel greyed out — and retrying the same address reported success
   without pulling, so there was no way to recover from inside the app.

**The durable lesson:** a green end-to-end test proved nothing here, because it
constructed its own subject. The bugs lived in the difference between a notebook
the test made and a notebook a person had.
